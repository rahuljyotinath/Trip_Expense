# Path shapes for the prototype

## Question

What are the **2–3 competing full paths** we should build as throwaway UI variants? Each path must cover all three moments:

1. New phone opens `/?join=CODE`
2. Organizer creates a trip and logs the first spend
3. Same browser returns with a saved seat

Strawmen to stress-test (not prescriptive):

- **Collapse** — join link skips extra steps: one name field (auto-claim closest roster nickname); first spend is amount + reason only; defaults payer=you, split=everyone, date=today
- **Wizard** — one question per screen from seat through first spend
- **Line** — ledger-first: type `800 dinner` (or similar) on the trip view; system infers payer/split or asks only when ambiguous

What else belongs in the set? What must each variant explicitly **not** do so comparisons stay fair?
